## U-20261008-02 · 2026-10-08 · Runs have an ID, a result and kept failure artifacts · #done #feature #artifacts

- **What** (`progress.md` #7, phase 2 of the platform roadmap, PR #32): `parallel_run` started its runners and waited, and nothing recorded how they ended; a runner that failed left no trace and did not change the outcome.
  - **Run**: `execute_yaml` opens a `RunSession` with a run ID (`20261008T031542Z-9f2c1a7b`, or the caller's) and returns a `RunResult`: every step and every runner execution with its status, timing and message. It used to return `None`.
  - **Artifacts**: `<artifacts_path>/<run-id>/runners/<runner>/<nn>-<step>/` per runner execution and `testpioneer/{execution.log,manifest.json}`. `keep_artifacts` is `on_failure` (default: a run that passed leaves nothing, a failed one keeps what did not pass), `always` or `never`. Both are new optional top-level YAML keys and `RunOptions` fields.
  - **Runner contract**: each runner execution gets `TEST_PIONEER_RUN_ID` and `TEST_PIONEER_ARTIFACT_DIR`. A runner that ignores them is wrapped: a sub-process writes to `stdout.log` / `stderr.log` (copied to the console from the wait loop) and its exit code is recorded; an in-process call has `sys.stdout` / `sys.stderr` copied to the same files. No thread is used, because screen recording replaces `threading` with greenlets.
  - **Adapter**: `runner/adapter.py` defines `RunnerAdapter` and `ModuleRunner`; `RUNNERS` in `runner/registry.py` replaces the plain name-to-package table.
  - **CLI**: `python -m test_pioneer run <file> [--run_id] [--artifacts_path] [--keep_artifacts]` exits 1 when the run did not pass. `-e` still exits 0 whatever the steps did.
  - Step messages reach the run's `execution.log` through a sink in `step_log_check`, so the `TestPioneer` logger stays silent unless `pioneer_log` is set, as before.
- **Compatibility**: a failed `parallel_run` runner still does not stop later steps; it now makes the step and the run `failed`. Exceptions propagate as before, after the run is recorded as `error`. A handler called outside `execute_yaml` finds no session and starts its process exactly as before. An `OSError` while collecting artifacts becomes a warning on the result.
- **Found while here**: all five runner packages exit 0 when an action of a script fails and none reads an artifact directory from the environment (`architecture.md` §6, `progress.md` #13), so an exit code marks a run `failed` only for a missing or malformed script. `process_manager_instance.name_set` is never emptied between calls (`progress.md` #12).

## U-20261008-03 · 2026-10-08 · Runner reports are read and merged into one report · #done #feature #report

- **What** (`progress.md` #8, phase 3 of the platform roadmap, PR #32): each runner wrote its own report in its own format, wherever its script said, and a run had no report of its own. A failed action was invisible to TestPioneer, because the runners exit 0 either way (U-20261008-02).
  - **Collecting**: a step names the files its runner writes with `artifacts:` (a list of patterns for `run` and `run_folder`, one list per script for `parallel_run`). When the runner ends, the files changed since it started are copied to `collected/` in its artifact directory. A pattern that is absolute or contains `..` is refused; the run's own artifact directory is never collected into itself.
  - **Reading**: `report/readers.py`. `RecordPairReader` reads the `*_success.json` / `*_failure.json` pair that the API, web, load and GUI runners write; each record becomes a `CaseResult`. Only the field names differ per runner, and each adapter in `RUNNERS` carries its reader. Web and GUI action parameters are left out of the test name, since they can hold typed secrets.
  - **Status**: a runner execution that ended normally but recorded a failed test is `failed` ("1 of 2 recorded test(s) failed"), and so are its step and the run.
  - **Report**: `report/testpioneer-report.json` (the canonical `RunResult`, now with `cases`, `report` and `reports`), `report/testpioneer-report.html` (one self-contained page without script: steps, runner executions, recorded tests, links to the kept artifacts and raw reports) and optional `report/testpioneer-junit.xml`. `report_path` and `report_formats` are new optional top-level keys, `RunOptions` fields and `run` options (`--report_formats json,html,junit` or `none`).
  - **Validation**: the schema knows the new keys; the linter reports `artifacts` and `scripts` of different lengths (`artifacts-scripts-mismatch`, error) and a pattern that would be refused (`artifact-pattern`, warning).
- **Design notes**: no XML is parsed, so nothing here is exposed to XML entity attacks; JUnit XML is only written, as escaped text. A report that is malformed or over 50 MB is not read: the runner keeps its status, a warning is recorded and the raw file stays in the artifact directory. A report that cannot be written is a warning too.

## U-20261008-08 · 2026-10-08 · A workflow can run twice in one process: step names are unique per run · #done #bugfix

- **Bug** (`progress.md` #12, decided by the owner's delegation): `_validate_steps` added every step name to `process_manager_instance.name_set`, and nothing emptied the set. A second `execute_yaml` call in the same Python process that reused a name, which is every repeated run of one workflow, stopped with "job name duplicated" before running a step. Only the test suite noticed, and it cleared the set between tests.
- **Fix**: `_validate_steps` empties `name_set` first, so a name has to be unique within its workflow and no further. Closing a program never depended on that set: `close_program` looks the name up in `process_dict`, so a program an earlier call left open can still be closed. What would have gone wrong instead is caught where it happens: `open_program` now fails with "A program named <name> is already open" rather than replace the entry and leave the first program without a name to close it by.
- **Tests**: `test/test_pioneer_executor.py` +2 (the same names validate twice; the same workflow runs twice in one process), `test/test_external_program.py` +1 (a name that is still open is not opened again and keeps its program). The three fail on the old code.
- **Docs**: `docs/yaml-configuration.rst`, `docs/step-types.rst` (`open_program`), `docs/migration.rst`.
- **Files**: `test_pioneer/executor/pioneer_executor.py`, `test_pioneer/executor/program/external_program.py`, the tests and docs above, `progress.md`.
