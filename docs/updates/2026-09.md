## U-20260923-01 · 2026-09-23 · The step log is written as UTF-8 · #done #logging

- **What**: `TestPioneerHandler` (`test_pioneer/logging/loggin_instance.py`) opened the `pioneer_log` file named in the user's YAML with the locale encoding. ## U-20260923-02 · 2026-09-23 · run_folder works for the web, api and load runners · #done #bugfix

- **Bug** (`progress.md` #5, was [UNVERIFIED]; confirmed): a `run_folder` step handed the runner the list of JSON files in the folder, but for `web-runner`, `api-runner` and `load-runner` the runner was each framework's `execute_action`, which takes one action list, so every file path was rejected as a malformed action ("executor received invalid data") and nothing in the folder ran. Only `gui-runner` was mapped to `execute_files`.
- **Fix**: in `run_folder` mode all three map to their framework's `execute_files` (each exports it at top level); `run_folder` passes the files as sorted string paths. Also, AutoControl is now imported only for a `gui-runner` step: it was imported for every step whenever `je_auto_control` was installed, and where it is installed without its Qt dependencies (as in this repository's `.venv`) any web/api/load step failed at import.
- **Tests**: `test/test_run_utils.py` +2 (`run` resolves each runner's `execute_action`, `run_folder` its `execute_files`); `test/test_run_folder_files.py` (2): the runner receives the folder's `.json` files as sorted strings, and end to end with LoadDensity's executor both files' actions run. Three of these fail on the old code. Suite: 114 passed.
- **Files**: `test_pioneer/executor/run/utils.py`, `test_pioneer/executor/run/executor_run_folder.py`, `test/test_run_utils.py`, `test/test_run_folder_files.py`, `progress.md`.
