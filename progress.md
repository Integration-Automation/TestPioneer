- **#13** The runner packages do not read `TEST_PIONEER_ARTIFACT_DIR` yet, and all but LoadDensity's `dev` branch exit 0 when an action fails. What native support means is written down (`docs/artifacts.rst`, "Native Support"; `architecture.md` §6) and TestPioneer already handles a runner that has it; until then a step declares its report files with `artifacts:`. The change needs no release of `je_action_core` and is one pull request to `dev` per runner repository. As read from their `dev` branches on 2026-10-08:
  - **Exit status**, the way LoadDensity did it in its PR #118 (`je_load_density/__main__.py`, `_execute_cli_actions`: the executor's reporter is wrapped for the run, `on_failure` is counted, and the CLI raises when the count is not zero):
    - APITestka: `__main__.py`, and `apitestka run` in `cli/cli_main.py`. A failed request does not raise there; it is only appended to `test_record_instance.error_record_list`, so the count has to include what that list gained. `cli_common.run_action_path` is also behind `openapi --run`, `contract`, `spec check` and `trend`, which should keep their meaning.
    - WebRunner: `utils/cli/cli_main.py`, `_dispatch`. `_run_one_file` already tells a failed file for the ledger; recording is off by default, so the reporter's `on_failure` is the signal to count.
    - FileAutomation: `__main__.main`, the legacy dispatch. It writes no report, so this is all it needs.
    - AutoControlGUI: `--execute_file` in `__main__.py`. `recorded_failures()` exists and its `run` command already exits 1 with it.
  - **Report location**: the report writers open `name + "_success.json"` and the like relative to the working directory (`utils/generate_report/` in APITestka, WebRunner and LoadDensity; AutoControlGUI's report generators). One helper that places a relative name below `TEST_PIONEER_ARTIFACT_DIR`, used by those writers, is all it takes.
  - Nothing stands in the way: the shared request record that is being introduced (ActionCore PR #1, APITestka PR #146) touches neither the entry points nor the report writers, and PyBreeze only displays a runner's exit status. APITestka, WebRunner and LoadDensity each have a contract test for the legacy flags (`test_legacy_cli_contract.py`) to extend.
  - When a runner has both, the note on exit status in `docs/artifacts.rst` and `docs/reports.rst` and the entries in `architecture.md` §6 change with it, and the `artifacts:` lines of the README example can go.
